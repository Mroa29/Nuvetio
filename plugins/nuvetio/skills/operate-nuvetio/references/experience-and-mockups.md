# Experiencia, flujos y mockups

Usar esta perspectiva cuando el usuario necesite comprender o visualizar cómo se utilizará el producto.

1. Definir la tarea principal y el punto de entrada del usuario.
2. Dibujar el flujo mínimo: inicio, decisiones, estados vacíos, éxito y recuperación de errores.
3. Describir cada pantalla por objetivo, contenido, controles y respuesta del sistema.
4. Si existe capacidad visual, crear un mockup coherente con el flujo aprobado.
5. Si no existe, entregar un wireframe textual accionable con jerarquía, componentes y comportamiento responsive.
6. Revisar claridad, accesibilidad, carga cognitiva y mensajes de error.

No decorar antes de resolver el flujo. Distinguir claramente entre concepto, wireframe, mockup y interfaz implementada.
